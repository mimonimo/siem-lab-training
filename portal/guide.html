침해 웹서버 로그 분석 실습 교안

여러 종류의 보안 로그를 Wazuh SIEM으로 분석해, 흩어진 흔적을 시간·IP·계정으로 연결하고 실제 침해와 미끼(정찰/정상업무/방어성공)를 구분하는 CTF형 실습입니다. 이 교안은 배경지식이 없어도 따라올 수 있도록 구성도·시나리오·분석 방법·주의점을 정리했습니다.

1네트워크 · 시스템 구성도

이 실습 서버 한 대에 웹서버·로그·SIEM·문제풀이 포털이 모두 올라가 있습니다.

2침해 시나리오

하나의 로그 뭉치에 여러 사건이 섞여 있습니다. 일부는 이어지는 공격 체인, 일부는 판단력을 시험하는 미끼입니다.

#스토리라인성격핵심 로그
ASSH 브루트포스 → 웹셸(search.php) → 페이로드 다운로드 → cron 지속성 → /usr/bin/backup 변조체인auth · access · audit · cron
B야간 sudoers.d 백도어 등록 (NOPASSWD 권한 상승) — A와 동일 공격자체인auth · audit
E파일 압축(tar) 후 외부 유출(curl → 198.51.100.47) — 체인의 마지막체인access · audit
C스캐너 정찰 (sqlmap UA, 다수 404, 방화벽 포트스캔 차단) — 실제 침해 아님미끼access · error · ufw
D정상 관리자(opsadmin)의 야간 배포 cron — 공격처럼 보이나 정상미끼auth · cron
F반복 로그인 실패 후 계정 잠금 — 방어가 작동, 대응 불필요미끼auth

공격 체인 A → B → E 는 동일 공격자(198.51.100.23 / 계정 webadmin)의 침투→권한상승→정보유출로 이어집니다. C·D·F 는 서로 무관한 노이즈로, "알림이 떴다고 다 대응하는 게 아니다"라는 판단을 훈련합니다.

3로그 소스 읽는 법

로그무엇이 보이나의심 포인트
access.log웹 요청(IP·시각·URL·상태·UA)URL의 cmd= 파라미터 = 웹셸 명령 실행
error.log웹 서버 오류·없는 파일 접근다수 "File does not exist" = 스캔 흔적
auth.logSSH·sudo 인증다수 Failed 후 Accepted = 브루트포스 성공
audit/audit.log프로세스 실행(execve)·파일 변경key= 값(webshell_exec / priv_esc / cron_persist / bin_tamper)
cron.log예약작업 등록·실행비정상 경로(/tmp/...) 반복 실행 = 지속성
ufw.log방화벽 차단한 IP가 여러 포트 = 포트 스캔
mail.log메일 송수신대부분 정상 노이즈

4분석 방법론 — 어떻게 접근하는가

  1. 기점 잡기 — 인증 로그에서 "다수 실패 후 성공"을 찾아 최초 침투 시각·IP·계정을 확정합니다.
  2. 피벗(pivot) — 그 IP/계정을 data.srcip·data.dstuser로 필터해 같은 주체의 다른 행위를 모읍니다.
  3. 시간축 연결 — 웹셸 배치 → 명령 실행 → 다운로드 → 지속성 → 변조 → 권한상승 → 유출을 시간순으로 잇습니다.
  4. 교차 확인 — access.log의 요청과 audit.log의 프로세스 실행을 같은 시각으로 대조해 "정말 실행됐는지" 확인합니다.
  5. 미끼 걸러내기 — 알림/이상 로그가 실제 침해로 이어졌는지(성공 응답·후속 행위) 따져 대응 우선순위를 정합니다.
💡 핵심 관점 — SOC 분석은 "알림 개수"가 아니라 "조사 후 대응이 필요한가"로 판단합니다. 정찰(C)·정상업무(D)·방어성공(F)은 흔적이 남아도 대응이 불필요할 수 있습니다.

5Wazuh 사용법 (빠른 참조)

  1. 접속 — https://이_서버_IP → 계정 admin 으로 로그인.
  2. Discover 메뉴 → 인덱스 패턴 wazuh-alerts-*(탐지 알림) 또는 wazuh-archives-*(모든 로그 검색).
  3. 저장된 검색(Open) — 🌐 웹 접근 로그, 🔐 인증 로그, 🧱 방화벽 로그, 🚨 탐지 알림 을 열면 깔끔한 컬럼으로 바로 봅니다.
  4. 검색 예시 — data.srcip:"198.51.100.23" · rule.id:100101 · full_log:"search.php"

6주의점

  • 시간 필터 함정 — 로그는 기준 시각(포털 상단 표기) 이전 24시간에 분포합니다. Discover가 비어 보이면 우측 상단 시간 범위를 Last 1 year 로 넓히세요.
  • 알림 ≠ 침해 — 미끼(C·D·F)도 알림/이상 로그를 남깁니다. 조사 후 대응 필요성으로 판단하세요.
  • 안전한 실습 — 모든 공격 아티팩트(웹셸·백도어·변조 바이너리)는 실행되지 않는 더미입니다. 실제 악성코드가 아닙니다.
  • 답안 형식 — 포털의 "답안 형식"에 맞춰 입력하세요(시각 HH:MM:SS, IP xxx.xxx.xxx.xxx). 오답은 감점, 힌트는 소폭 감점됩니다.
